# Napkin Studio Asset Governance Rule

## Permanent rule
No asset is created unless it has:

1. **A single owner** responsible for completion and revision.
2. **A review status** using one of: Briefed, Drafting, In Review, Revision, Approved, Rejected.
3. **A destination** using one of: Deck, Bible, Website, Production, Marketing, Archive.
4. **A source-of-truth file** in GitHub.
5. **A canon dependency note** identifying which approved files it relies on.
6. **A clear problem it solves** for development, commissioning or production.

## Approval rule
No specialist agent may lock canon. Specialists propose. The Project Showrunner integrates. The Executive Showrunner approves. Only approved material may be promoted into canonical files.

## Asset header
Every working file must begin with:

- Project
- Asset owner
- Status
- Destination
- Canon version read
- Dependencies
- Problem solved
- Assumptions introduced
- Approval required from

## Anti-waste rule
If an asset has no defined destination or commissioning value, it is paused before production begins.

## Version rule
Working material stays on a development branch until reviewed. Approved material is merged through a pull request with a change note explaining what changed and why.
